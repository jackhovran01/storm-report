# storm-report

基于斯坦福 **STORM**（Synthesis of Topic Outlines through Retrieval and Multi-perspective Question Asking）方法的行业 / 市场研究报告生成 skill。

把「写研究报告」从一次性生成，改造为一条研究驱动流水线：

> 大纲 → 视角与议题 → **议题驱动对抗辩论**（检索式辩护）→ 证据库 → 分节写作 → 组装审校

产出结构化、可溯源、带权威信源（A/B 级白名单）与 GB/T 7714-2015 引用角标的 HTML 报告。

---

## 目录结构

```
storm-report/
├── SKILL.md                      # skill 主指令（七阶段流程 / 硬约束 / 预算档位）
├── references/
│   ├── source-whitelist.md       # A/B 级权威信源白名单 + 付费墙处理规则
│   └── gbt7714.md               # GB/T 7714-2015 引用格式 + 编号锁定规则
├── scripts/
│   └── build_report.py           # report.md → 独立 HTML（含 --lint 自动校验）
└── tools/
    └── colab_upload.ipynb        # 从 Google Colab 推送本仓库到 GitHub 的脚本
```

所有文件**无第三方依赖**：`build_report.py` 仅使用 Python 标准库（argparse / html / math / os / re / sys），任意 Python 3 环境可直接运行。

## 快速开始

### 在 WorkBuddy 中使用

1. 把本仓库内容复制到 `~/.workbuddy/skills/storm-report/`。
2. 在对话中输入 `/storm-report`，或直接说「用 STORM 方法写一份 XX 行业报告」。

### 其他 agent 平台

本 skill 与平台解耦，可移植到任何具备 **LLM + 联网检索** 能力的 agent。见下方「移植映射」。

### 只想要 Markdown → HTML 渲染器

仅取 `scripts/build_report.py` 即可，无需 SKILL.md 与 references。

## 七阶段流程

| 阶段 | 名称 | 关键产出 | 是否停等 |
|---|---|---|---|
| 0 | 需求解析与预算确认 | 调研任务卡（主题 / 边界 / 受众 / 档位） | 否 |
| 1 | 大纲生成 | 报告大纲（约 9 节默认结构） | 否 |
| 2 | 视角生成与议题提炼 | 视角 + 立论清单（含 1 红队）+ 核心争议议题表 | **确认点①** |
| 3 | 议题驱动对抗辩论 | 各议题交锋记录 + 交锋记分牌（证据驱动） | 否（内部） |
| 4 | 对抗性检索 → 证据库 | 证据库（固定 `[n]` 编号）+ 共识区 | **确认点②** |
| 5 | 分节写作 | report.md（句末上标角标 `[n]`） | 否 |
| 6 | 组装与审校 | report.html + 自审 + `build_report.py --lint` | 否 |

### 五条不可妥协的硬约束

1. **信源白名单**：只引用 A/B 级权威信源（官方一手数据、权威媒体、权威券商研报、权威咨询机构）。
2. **引用规范**：句末上标角标 `[n]`（顺序编码制）+ 文末 GB/T 7714-2015 参考文献表。
3. **编号锁定**：`[n]` 在阶段 4 进入证据库时即固定，阶段 5 写作只复用、不重排。
4. **防幻觉**：每条关键数据 ≥2 个 A/B 级来源交叉验证；来源冲突标「来源分歧」，不强行统一。
5. **人机交互**：全程 2 个确认点（阶段 2、阶段 4），到达时停等人类确认。

### 预算三档

| 档位 | 视角数 | 争议议题 | 每议题轮次 | 检索预算 | 适用场景 |
|---|---|---|---|---|---|
| 精简 | 3（含 1 红队） | 2 | 1 | ≤12 次 | 快速研判、内部备忘 |
| 标准（默认） | 5（含 1 红队） | 3–4 | 2 | ≤25 次 | 常规行业 / 市场研究报告 |
| 深度 | 7（含 1 红队） | 5 | 3 | ≤45 次 | 跨领域、争议极大、需对外交付 |

## 交付物

输出到 `{workspace}/outputs/<主题>-<YYYYMMDD>/`：

| 文件 | 内容 |
|---|---|
| `report.html` | **主交付**：目录、执行摘要、正文（可点击上标角标）、SVG 图表、参考文献表 |
| `report.md` | 报告 Markdown 源（便于再编辑与版本管理） |
| `evidence.md` | 证据库（固定编号、正方 / 反方分列、仲裁倾向、共识区） |
| `outline.md` | 大纲 + 视角立论清单 + 核心争议议题表 |

## build_report.py 用法

```bash
# 生成 HTML（校验发现 ERROR 时以退出码 1 结束）
python build_report.py report.md -o report.html --strict

# 只做引用校验，不生成 HTML
python build_report.py report.md --lint

# 自定义标题
python build_report.py report.md -o report.html --title "2026 光模块行业报告"
```

### report.md 输入约定

- 第一个 `#` 标题作为报告标题（不进目录）。
- 正文引用用上标角标 `[1]` / `[2,3]` / `[4-6]`；**仅 1–3 位数字**被视为引用（`[2024]` 等年份不会误判）。
- 图表用 ```chart 围栏块，支持 `bar` / `line` / `pie`：
  ```
  ```chart
  type: bar
  title: 市场规模（亿美元）
  data: 2021,75;2022,92;2023,105
  ```
  ```
- `## 参考文献`（或 `## References`）之后每行一条文献，行首 `[n]`，行尾附 `[A级]` / `[B级]` 可信级别徽标；`>` 开头行渲染为表下注释。
- 支持表格、有序 / 无序列表、`> 引文`、`**加粗**` / `*斜体*` / `` `代码` ``。

### `--lint` 自动检查项

引用断号、悬空引用（正文引了表外编号）、未引用文献、编号重复、EB/OL 缺 URL、网络文献缺引用日期 `[YYYY-MM-DD]`、缺可信级别徽标、命中低质信源域名黑名单（baijiahao / toutiao / uc.cn / 360kuai 等）。**ERROR 清零后方可构建最终 HTML。**

## 移植映射（移植到其他 agent 平台时）

| WorkBuddy 能力 | 在 skill 中的作用 | 通用替代方案 |
|---|---|---|
| **WebSearch** | 阶段 1/3/4 检索官方与权威证据 | 任何联网检索：SerpAPI / Bing / Brave / 直接抓取；**必须能限定域名白名单** |
| **Agent 子代理** | 阶段 3 每个视角由独立 subagent 承载，互不共享中间结论（防同质化） | 多智能体编排：LangGraph 多节点 / AutoGen group chat / OpenAI Assistants 多 thread 等；各视角保持**独立上下文** |
| **Skill 工具** | 加载 SKILL.md 指令 | 把 SKILL.md 作为 system prompt 注入，或放入目标平台 skills 目录 |
| **工作区记忆** | 阶段 4 回读前序会话已核实结论，避免写过时数据 | 长期记忆 / 知识库 / 向量库；**可选但强烈建议** |
| **文件系统读写** | 写 report.md / evidence.md / outline.md | 目标平台沙箱或本地磁盘 |
| **build_report.py** | 阶段 6 渲染 HTML | Python 3 直接运行；不具备则只保留 `report.md` |
| **人机交互停等** | 2 个确认点暂停等确认 | 支持交互式暂停则用原生暂停；不支持则改为一次性产全中间文件后人工审阅 |

### 三种移植形态

- **A 完整**：保留七阶段 + 独立子代理承载视角。质量最高，要求多 agent 编排与检索配额切分。
- **B 精简**：单上下文内串行扮演各视角（须显式标注「反同质化保障降级」），红队仍须独立执行。
- **C 只取渲染器**：仅搬运 `scripts/build_report.py`。

## 已知坑

1. **趋同检测**：同一 LLM 生成的多个 persona 天然趋同。若所有议题正反方结论一致 → 判定「辩论失效」，须由红队单独补一轮质询；仍无分歧则标注「未形成有效对抗，结论置信度下调」。
2. **引用语义对应**：编号层校验通过 ≠ 内容正确。典型事故：把 A 公司数据挂在 B 公司论断上、用「发货量说明」支撑「创始团队背景」、写作时凭印象补事实再就近挂编号。**强制 100% 回查**：企业归属与股权、创始人背景、任何具体数值、技术路线归属方。
3. **跨语言术语**：凡技术归属 / 工艺名 / 器件名论断，必须回溯一手英文原文逐字比对。已实测高频误译：`microlens → Metalens`、`roll-to-roll → roll-to-plate`、`Si lens → 超透镜`。一个词足以反转结论方向。
4. **编号锁定**：阶段 4 分配 `[n]`，阶段 5 只复用；被删来源编号不回收（占位），避免整体错位。
5. **预算触顶即停**：检索预算耗尽时，未决议题标注「检索预算耗尽，证据偏单侧」，不得硬撑。

## SKILL.md frontmatter 说明

`SKILL.md` 顶部 YAML 块是 WorkBuddy 专属元数据，移植时可忽略或改写：

- `name`：skill 名（调用名）。
- `description`：触发词与适用场景描述。
- `agent_created: true`：标记为用户自建 skill，仅 WorkBuddy 内部使用。

正文（七阶段流程、约束、预算）与 frontmatter 无关，可直接作为指令使用。
